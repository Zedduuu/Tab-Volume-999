# Tab Volume 999 — Edge 标签页音量扩展

> 🤖 **AI 辅助开发声明**
>
> 本项目在开发过程中使用了 **AI 编程助手（Cline）** 辅助编写代码与文档，并经过**人工逐行审查、
> 边界测试与实际使用验证**后才发布。仓库提交历史中未刻意区分 AI / 人工编写的内容；
> 后半部分「面向开发者」章节记录了完整的技术决策与实现路径，供后续维护与审计参考。

独立调节**每个标签页**的音量：**0% ~ 999%**，各标签页设置互不影响。
点击扩展图标后，在弹出面板里**滚动鼠标滚轮**即可实时微调（也支持滑块、按钮）。
**100% 位于仪表盘与滑块的物理中心**，滚轮每次 ±5%（按住鼠标左键为 ±20%）。

![license](https://img.shields.io/badge/license-GPL--3.0-blue) ![mv3](https://img.shields.io/badge/Manifest-V3-brightgreen)

> 兼容 Microsoft Edge 与 Chrome（Chromium 109+，Manifest V3）。
> 界面支持 **简体中文 / English / 日本語 / 한국어**：默认跟随浏览器语言，
> 也可点面板右上角 🌐 手动切换并记住选择。

## 第一部分 · 面向用户

### 📦 安装

1. 打开 Edge 地址栏输入 `edge://extensions/` 并回车；
2. 打开左上角「**开发人员模式**」开关；
3. 点击「**加载解压缩的扩展**」，选择本项目目录 `tab-volume-999`；
4. 在工具栏把本扩展「固定」到图标区，方便随时点开。

> 安装时 Edge 会提示权限「**捕获屏幕内容**」——这是 `tabCapture` 权限的固定提示，
> 本扩展**只在**你点开面板的那个标签页上捕获音频，不读取也不记录任何页面数据。

### 🎚️ 使用方法

1. 切到想调节的标签页，点击扩展图标；
2. 在面板**任意位置滚动滚轮**：滚上 = 音量 +5%，滚下 = 音量 -5%；
   - **按住鼠标左键**再滚 = 每次 ±20%，快速调节；
3. 也可以：拖滑块（0~999，**100% 位于滑块中心**）、点 −/＋ 按钮（±5%）；
4. 🔇 静音会记住当前音量，点「恢复」或调高音量即可自动恢复；
5. 关闭面板后设置依然生效；切到别的标签页，各自的音量互不影响；
6. 想完全停止接管（消除约 20~50ms 的捕获延迟）时，点底部「**⇤ 释放接管**」，
   标签页立即恢复原生播放；之后任意调节音量会自动重新接管；
7. 调音量时，扩展图标右下角会出现一个**不带背景的数字**（绿 = ≤100%，
   紫 = >100%，红 = 0 或静音），切换标签页时能瞄一眼各自的音量；
8. 点「**📖 操作 & 说明**」按钮，弹窗会整体加宽、说明面板从最左侧
   「长出」（操作方式 + 关于本扩展），主面板完整右移、不被遮挡；滚轮
   始终只用于调音量，互不干扰。

### 🛡️ 隐私与权限

本扩展**不收集、不上传任何用户数据**（完整声明见 [PRIVACY.md](PRIVACY.md)）：

- 音量设置仅保存在你本机的浏览器存储（`chrome.storage.local`），卸载即清除；
- 音频流只在打开面板的会话内被临时捕获、用于本地放大，关闭即释放；
- 没有分析、广告、追踪 SDK，也不含任何远程代码。
### 🔧 已知限制

- 不能在扩展图标上悬停滚轮调节（浏览器不暴露图标的悬停/滚轮事件，只能点开面板操作）；
- 接管后音频有约 20~50ms 延迟（捕获-回放的固有代价），观感上可忽略；
- 音量超过约 200% 后，增益放大会明显失真（超出硬件/数字上限的物理限制），
  适合应急放大场景，日常建议 ≤ 200%；
- 浏览器内置页面（`edge://*`、扩展商店、PDF 查看器等）无法接管，面板会提示失败；
- 如果标签页正被**其他扩展/系统录屏**占用，捕获会失败，关闭那个录制后点面板里的「重试接管」即可；
- 标签页被手动点喇叭静音后再停用本扩展，会还原为原来的静音状态（不会误开声）；
- 浏览器重启后各标签页音量设置重置为 100%（`onStartup` 会自动解除残留静音）。

### 🔍 故障排查

| 现象 | 处理 |
|---|---|
| 面板提示「无法接管音频：该标签页正被录制…」 | 说明有其他软件/扩展在录制该标签页，停用后再点「↻ 重试接管」 |
| 面板提示「无法接管音频：浏览器拒绝…」 | 检查浏览器是否通过策略/安全软件禁用了 `tabCapture` |
| 某个网站永远接不上（其它网站正常） | 该站可能开启了 DRM 或特殊播放保护，属浏览器限制，无法绕过 |
| 页面刷新后没声音 | 等待约 1.5 秒自动重捕；若仍失败，重新打开面板即可恢复 |
| 面板提示「无法接管音频：Cannot access…」 | 当前是浏览器内置页面，换普通网页即可 |

### ❓ 常见问题

**Q：为什么不能像某些工具那样"直接在图标上滚轮调节音量"？**
A：浏览器扩展 API 只提供「点击图标」事件，不暴露图标上的悬停/滚轮事件，这是平台硬限制；
本扩展的折中方案是点击图标后在面板内滚轮调节。

**Q：100% 音量时也有延迟吗？**
A：没有。音量为 100% 或「⇤ 释放接管」时，标签页**原生播放、零延迟**；只有实际放大或
缩小时才走接管管道。

**Q：会永久改变网页或系统的音频吗？**
A：不会。设置仅保存在扩展自己的本地存储里；卸载扩展或浏览器重启后即恢复原生状态。

## 第二部分 · 面向开发者

### 🧭 技术实现路径

以下是本项目从需求到落地的完整技术决策过程，按开发顺序记录。

**1. 需求拆解**

- 每个标签页独立调节音量，范围 0% ~ 999%（超过 100% 用于应急放大）；
- 操作入口轻量：点击扩展图标 → 面板内滚轮即可调节；
- 对网页内容"无感"：不注入脚本、不要求网站配合。

**2. 方案选型（为什么是"音频接管"）**

| 候选方案 | 致命问题 |
|---|---|
| content script 调 `HTMLMediaElement.volume` | ① 只能 0~1，**无法超过 100%**；② 受 CORS 限制，无法作用于跨域音频；③ 对 WebAudio 游戏无效；④ 页面刷新/导航即失效 |
| 修改浏览器内部音量（无此 API） | 不存在 |
| ✅ **tabCapture 音频接管**（本项目采用） | 接管标签页**全部**音频流，增益 0~9.99 倍，**无 CORS 限制** |

**3. Manifest V3 的两个关键约束与对策**

- `chrome.tabCapture.getMediaStreamId()` **必须在用户手势上下文**（点击 popup）中调用
  → 由 `popup.js` 在点击事件里发起整个接管流程；
- 接管后的 AudioContext 必须运行在**离屏文档**（offscreen document, reason `AUDIO_PLAYBACK`）
  中，不能放在 service worker（生命周期短、无 DOM、无法持续播放）
  → 由 `background.js` 负责离屏文档的创建与保活。

**4. 权限模型（最小化，逐个都有明确用途）**

| 权限 | 用途 |
|---|---|
| `tabCapture` | 获取标签页音频流 + 将原标签页静音（防回声） |
| `offscreen` | 创建离屏文档承载 AudioContext |
| `storage` | 本地持久化各标签页音量设置 |
| `activeTab` | 定位当前激活标签页以获取其音频流 |

**5. 音频链路设计**

```text
popup（用户手势）
  → chrome.tabCapture.getMediaStreamId({ targetTabId })
  → background 创建/复用离屏文档
  → offscreen: getUserMedia({ chromeMediaSource: 'tab' }) 取该标签页音频流
  → 音频流 → MediaStreamAudioSourceNode → GainNode → AudioContext.destination（扬声器）
  → 原标签页 setMuted(true)，避免双重声音
  → 音量调节 = 修改 GainNode.gain（volume/100 × 1 → 0 ~ 9.99 倍）
```

**6. 状态模型与持久化**

- 每个标签页一个独立会话 `{ volume, muted }`，天然互不影响；
- `background` 是状态的**权威来源**：负责落盘 `chrome.storage.local`、转发给离屏音频引擎、
  维护图标徽标；
- `popup` 只做本地乐观更新 + 节流上报（60ms 合并），保证滚轮调节手感流畅不闪烁。

**7. 断线自动重捕**

- 页面刷新 / 导航 / 音视频暂停后恢复会导致 `MediaStreamTrack` 中断（触发 `ended`）；
- 离屏文档检测到流结束 → 上报 `background` → **自动延迟重试**重新接管；
- 用户侧表现为"刷新页面后约 1.5 秒自动恢复原音量"，无需重新点开面板。

**8. 图标徽标（badge）**

- 用 Canvas 把数字绘制到图标**右下角**，不占用扩展徽标的红色背景，可同时显示状态色
  （绿 = ≤100%、紫 = >100%、红 = 0 或静音），60ms 节流防闪烁；
- 好处：切换标签页时扫一眼工具栏就能知道每个标签页当前音量。

**9. 延迟优化与"零延迟旁路"**

- 接管管道固有 20~50ms 延迟（捕获、重新取流、渲染、声卡缓冲，各环节都有缓冲）；
- 这是「标签页音量接管」类扩展（包括 Volume Master）共同的成本，代码层面无法完全消除
  （`latencyHint` 等参数只能节省几毫秒）；
- **关键优化**：音量为 100% 或「⇤ 释放接管」时，标签页保持**原生播放、零延迟**；
  只有实际需要放大/缩小时才走接管管道，把延迟暴露降到最低。

### ⚙️ 架构与文件职责

```text
tab-volume-999/
├─ manifest.json          # MV3 清单（权限：tabCapture / offscreen / storage / activeTab）
├─ i18n-util.js           # i18n 运行时：加载语言包、按用户语言取词（zh_CN/en/ja/ko）
├─ _locales/              # 国际化语言包：en / zh_CN / ja / ko 各一份 messages.json
├─ background.js          # 后台：消息路由、离屏生命周期、状态持久化、接管/释放、断线重捕
├─ offscreen.html         # 离屏文档入口（不可见，真正发声的页面）
├─ offscreen.js           # 音频引擎：建流、增益、静音管理、会话清理
├─ popup/
│  ├─ popup.html          # 界面：环形仪表盘 + 大数字 + 滑块 + 按钮 + 说明面板
│  ├─ popup.css           # 主黑·副白·圆角样式
│  └─ popup.js            # 滚轮 / 左键快调 / 滑块交互、状态同步节流、接管流程
├─ icons/                 # 扩展图标（16/32/48/128，脚本生成）
├─ tools/make-icons.ps1   # 图标生成脚本（可重复运行）
├─ LICENSE                # GPL-3.0
├─ PRIVACY.md             # 隐私政策
└─ README.md              # 本文档
```

**运行时消息流**

```text
popup ── chrome.runtime.sendMessage ──▶ background ──▶ offscreen（音频引擎）
                                             │
                                             └─ chrome.storage.local（持久化）
```
